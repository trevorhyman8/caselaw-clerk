# How this system prevents hallucination

Two separate places a legal-blog drafting AI can go wrong, and what this
system does about each one.

## 1. Ingestion — where does the "evidence" come from?

Every case the system writes about is fetched from a **public, official
source** — the court's own PDF (via CourtListener's index, direct from
`cdn.ca9.uscourts.gov`, `courts.ca.gov`, etc.) or, for cases you forward
yourself, whatever you send. The moment a case is captured:

- The full opinion text and the original PDF are both stored, byte-for-byte.
- A **sha256 hash** is recorded for both — a fingerprint that changes if a
  single character changes. This is the "evidence locker," and it's
  **append-only**: nothing downstream (drafting, scoring, publishing) is
  allowed to edit or delete what's in it, only read it.
- Metadata (court, docket number, judge, filing date) comes from the
  source's own structured data, not from anything a model inferred.

**What this prevents:** the system can't "drift" — a draft written today
about a case is provably tied to the exact document that was fetched, with
a timestamp and a hash, and that document can always be re-checked against
the original.

## 2. Drafting + analysis — does the WRITTEN post actually say what the opinion says?

This is the harder problem, and it's where four independent checks run on
every draft before you ever see it. **All four must pass — one clean
opinion doesn't override a failure elsewhere.**

### Layer 1 — Every quote is checked character-for-character

If a draft says the court said something, the system verifies that exact
phrase (allowing for `...` where you legitimately trim a quote) appears
word-for-word in the stored opinion text. Not "roughly matches" — an exact,
mechanical substring check. A quote that doesn't check out doesn't get one
retry and then a shrug; it routes the whole draft to you for review.

*Proven during testing:* deliberately flipping one word in a real quote
("reversed" → "affirmed" — the opposite outcome) was caught instantly.

### Layer 2 — Every citation is cross-checked against the record

The case name, docket number, court, and date in a draft's closing citation
are checked against the locker's own metadata for that case — not
regenerated by the model. Any *other* case mentioned in the draft's own
commentary (outside a direct quote) either has to appear in the source
opinion itself, or gets checked against CourtListener's Citation Lookup
API — a tool the Free Law Project built specifically as an anti-hallucination
guardrail for exactly this purpose.

### Layer 3 — Facts about the case are extracted separately and cross-checked

Before drafting even starts, a separate pass reads the opinion and extracts
the procedural posture (motion to dismiss, summary judgment, etc.) and the
**holding direction** (did the court grant or deny, affirm or reverse) —
and every one of those extracted facts has to itself be a verbatim quote
from the source, checked the same way as layer 1. Then, when the draft is
written, its intro sentence is checked against those pre-verified facts.

A mismatch on **holding direction** — the single most damaging kind of
error for a litigation partner's blog — is a hard stop. It doesn't get
patched; the whole post gets redrafted from scratch.

### Layer 4 — An independent AI reviews the draft adversarially

A second, separate AI call — with no access to the style guide, no
knowledge it's reviewing "a draft," and instructions to be hostile and
pedantic — reads only the opinion and the draft, and lists every claim it
can't directly trace to the source.

*Proven during testing:* this layer caught a fabricated damages figure and
a fabricated dissenting opinion in a deliberately corrupted test draft — and,
in a real (not test) draft, caught something genuinely subtle: a quote
correctly pulled from the opinion's official "Summary" section, which the
court itself labels as *not part of the opinion* — the draft had
attributed that language to the judge's own reasoning. Both a human
reviewer and the first three layers could plausibly have missed that; layer
4 didn't.

## What you actually see

Every draft comes with a report card:

```
✅ VERIFIED — Doe v. MKS Instruments (C.D. Cal.)
├─ Quotes: 4/4 passages verified verbatim against the court's opinion
│   (84% of the post's body is the court's own words)
├─ Citation: parties ✓ docket ✓ court ✓ date ✓
├─ Facts: judge ✓ · court ✓ · posture ✓ · holding direction ✓
└─ Independent AI audit: 0 unsupported claims found
Source: [official court URL] · fetched [timestamp] · sha256 [hash]
```

If anything fails, you see exactly what and why — not a silently "cleaned
up" post. **Nothing is ever set to publish automatically.** Every draft
lands as a WordPress *draft* at most, and going live requires you to type
"publish," have the system read back exactly what it's about to post, and
then type "yes." A tap of a button is never enough on its own.

## Where this is provably grounded, not just a design doc

Everything above was tested against real, live, freshly-fetched court
opinions during development — not synthetic examples. The verification
gate has caught: a flipped holding, a fabricated damages award, a
fabricated dissent, and a subtle sourcing error in a court's own opinion
formatting. It has also correctly declined to pass a draft when the
underlying PDF text extraction itself had a page-break artifact — choosing
to ask a human rather than guess. See `verify/v1_results.json` and
`pipeline/ingest/GAPS.md` for the honest, unedited record of what was found
during testing, including the things that didn't work perfectly the first
time.
