03 · The Actual Software

The same six hand-offs, with the name on each toolbox. AI holds the pen in exactly three places — everything else is ordinary, checkable code.

Researcher
No AI
CourtListener APIcourts.ca.govCFPB newsroom feed
A listener, not a thinker. Polls the Free Law Project’s CourtListener database, reads the California Courts’ own opinion pages (where unpublished decisions live), and watches the CFPB newsroom. On a match it downloads the court’s official PDF and seals it in the evidence locker.
Editor
No AI
a Python scoring scripta weights file
Arithmetic. Court weight × topic points — the weights counted from your 2,939 posts — plus small bonuses for posture and familiar judges. The same case always gets the same score; there is nothing to hallucinate.
Writer
AI — Claude
Claude Sonnet 5 (Anthropic)
The one place AI holds the pen. Its standing instructions are the voice guide distilled from your archive; it is handed the three most similar posts you actually wrote plus the sealed opinion — and a hard rule: no legal knowledge from its own training. None.
Fact-checker
Mostly no AI
exact text matchingeyecite + Citation Lookupa fresh Claude call
The quote and holding checks are plain code — character-for-character matching, no judgment involved. Citations run through eyecite and the Free Law Project’s Citation Lookup service, built to catch fabricated cites. Only the fourth layer is AI: a fresh Claude call with no style guide and no hint it’s grading “a draft” — it can fail a draft, never rescue one.
Your phone
AI reads, code decides
Telegram bota state machine
A free Telegram bot that answers only your account — strangers get silence, not even an error message. Claude only interprets what you typed; deterministic code holds the keys, and typed “publish” then “yes” within 10 minutes is the only path through it.
Blog draft
No AI
WordPress.com official API
Plain code talking to WordPress.com’s official interface with credentials you create. “Draft” status is hard-coded — and until you flip publishing mode yourself, the publishing connection is never even created.
All of it runs in one small container on Railway — a receiver awake 24/7 for court alerts and your texts, and a scheduler that ticks every 30 minutes and decides what’s due.

05 · Where The Facts Come From

It is never allowed to write from memory — only from the court's own PDF, fingerprinted and sealed.

Court's PDF
→
Evidence locker
sha256 ad56c0ea5734…

The system never asks an AI “what did this case say?” It downloads the court's actual PDF from an official source, stores the exact text, and computes a sha256 fingerprint — a code generated from the document itself. Change one character anywhere in it, and the code changes. A tamper-evident seal.

The record is append-only — nothing downstream (drafting, checking, publishing) can edit or delete what's captured. “A case file that only grows.”

Real example: Coffey v. Fast Easy Offer, LLC — fetched from cdn.ca9.uscourts.gov, fingerprint ad56c0ea5734…

Every later step — drafting, checking, publishing — is only ever allowed to read that stored document, never an AI's general knowledge of the law.

06 · The Fact-Checker

Four independent checks stand between every draft and your phone. All four must pass.

1
Every quote, word for word
Checked character-for-character against the stored opinion. Not “sounds right” — an exact, mechanical match.
2
Every citation, cross-checked
Party names, docket, court, and date checked against the case record. Any other case mentioned is checked against a lookup tool the Free Law Project built specifically to catch fabricated citations.
3
The facts, extracted before a word is draftedHard stop
Judge, posture, and which way the court ruled — verified first. Getting the winner and loser backwards is the worst thing this system could do to your name, so that check has no shortcuts: a mismatch means a full rewrite, not a patch.
4
A second, independent AI, told to be hostile
No style guide, no idea it's reviewing “a draft.” Its only job: list anything it can't trace straight back to the opinion.
Any single failure routes the draft to you. Nothing gets “cleaned up” quietly.
07 · Proof, Not A Promise

It has already caught a flipped holding, a fabricated dissent, and something a careful reviewer could plausibly miss.

Planted test
Reversed → Affirmed
One word flipped in a real quote — the opposite legal outcome. Caught instantly by the word-for-word check.
Planted test
A fabricated damages figure and a fabricated dissent
Invented for a deliberately corrupted test draft. Both caught by the independent, hostile reviewer.
Real draft
A subtle sourcing error
The court's own opinion states its Summary section “constitutes no part of the opinion of the court.” A real draft quoted that summary correctly — but credited it to the judge's own reasoning. Layer 4 caught it; the first three layers, and a human skimming quickly, plausibly wouldn't have.
Real draft
Same case, two outcomes
Howard v. Republican National Committee was drafted twice. One draft's quotes checked out (4/4 exact, 58% of the body verbatim from the opinion) and passed. The other had a quote that didn't match the opinion word-for-word — quote coverage fell to 41%, below the system's own floor — and it was routed to needs‑review instead of publishing.
It has also refused to pass a draft when the underlying PDF text extraction itself glitched at a page break — choosing to ask a human rather than guess (documented candidly in the repo's own GAPS.md).

09 · How It Finds Cases

Three ways cases get in. The best one needs no new software on your side.

Automated feeds
CourtListener — a nonprofit's free, searchable archive of federal and state court opinions, run by the Free Law Project — plus California Courts and the CFPB's newsroom feed, checked continuously.
The honest number
Tested against 20 of your own old posts without the paid membership, the free tier alone found only 20% of them. Most of what you've historically written about are unpublished district-court orders — the ~$10/month membership's alert tools close most of that gap.
You, directly
Text the bot a case name, a docket number, or forward a Westlaw alert email you already get. Works regardless of the other two doors, and is likely the highest-coverage path of the three.

Appendix · For Reference

Every piece of software in this deck, one line each.

CourtListener / RECAP — a nonprofit's free, searchable archive of federal and state court opinions and dockets, run by the Free Law Project.
Telegram — a free texting app. The system shows up as a contact you message.
Railway — a company that rents a small computer that never sleeps. That's where the system lives.
WordPress.com — the service hosting the blog. The system can leave unpublished drafts there. Nothing more, until Scott says so.
Claude / Anthropic API — the AI doing the reading, writing, and checking. “API” just means the metered, pay-per-use way a server talks to it, instead of a person typing at a keyboard.
sha256 fingerprint — a code computed from a document. Change one character, the code changes. A tamper-evident seal.
RSS — a standard way a website announces “here's what's new,” which the researcher reads automatically.
Shadow mode — everything runs. Nothing can publish.
eyecite — free software from the Free Law Project that finds every legal citation in a block of text.
State machine — a small piece of ordinary code that can only move between a fixed set of steps in a fixed order. It's what makes “publish” then “yes” the only path to publishing.
